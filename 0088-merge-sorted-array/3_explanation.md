# 🧠 জুনিয়র ডেভেলপার গাইড: LeetCode 88 - Merge Sorted Array

স্বাগতম! এই গাইডটি সম্পূর্ণ বাংলায় এমনভাবে লেখা হয়েছে যাতে আপনি মুখস্থ না করে **প্রবলেমের পেছনের প্যাটার্ন (Pattern) এবং চিন্তা করার পদ্ধতি** একদম সহজে ধরতে পারেন।

---

## ১. 🧐 একদম সহজ বাংলায় প্রবলেমটা কী চাইছে?

আমাদের দুটো অ্যারে দেওয়া আছে: `nums1` এবং `nums2`।
* দুটো অ্যারেই আগে থেকেই **ছোট থেকে বড় সাজানো (Sorted)** আছে।
* আমাদের কাজ হলো: দুটোকে জোড়া লাগিয়ে (Merge করে) একটি সিঙ্গেল সাজানো অ্যারে বানাতে হবে।
* **শর্ত (Constraint):** আমরা কোনো নতুন অ্যারে বানাতে পারব না। যা করার, `nums1`-এর ভেতরেই করতে হবে (In-place)।
* এজন্য `nums1`-এর সাইজ আগে থেকেই বড় ($m + n$) করে রাখা আছে এবং পেছনের খালি জায়গাগুলো `0` দিয়ে পূর্ণ করা আছে।

---

## ২. ❌ নতুন বা জুনিয়র ডেভেলপাররা প্রথমে কী ভুল চিন্তা করে?

একজন সাধারণ ডেভেলপার প্রথমেই ভাবে:
> "আচ্ছা, আমি যদি সামনে (ইনডেক্স 0) থেকে তুলনা করা শুরু করি?"

**সমস্যাটা কোথায় হয় দেখুন:**
* ধরি, `nums1 = [4, 5, 6, 0, 0, 0]` আর `nums2 = [1, 2, 3]`।
* প্রথমে `nums1[0]` (মান: 4) এবং `nums2[0]` (মান: 1) তুলনা করলেন।
* যেহেতু `1` ছোট, আপনি `nums1[0]`-এ `1` বসিয়ে দিলেন।
* **বিপদ!** `nums1[0]`-এ আগে যে `4` ছিল, সেটা তো মুছে (Overwrite) গেল! মানটাই হারিয়ে গেল!
* সেই মান বাঁচাতে গেলে আপনাকে পুরো অ্যারে ডানে শিফট করতে হবে, যা কোডকে অনেক জটিল ও স্লো ($O(N^2)$) করে ফেলবে।

---

## ৩. 💡 আসল ট্রিক (The "Aha!" Moment): উল্টো দিক থেকে ভাবুন!

আমরা যদি সামনে থেকে না সাজিয়ে **পেছন থেকে সাজানো শুরু করি**, তাহলে কী হবে?

1. **খালি জায়গা কোথায় আছে?** $\rightarrow$ `nums1`-এর একদম পেছনে (Zeros)!
2. **সবচেয়ে বড় সংখ্যাগুলো কোথায় থাকে?** $\rightarrow$ যেহেতু দুটো অ্যারেই সাজানো, তাই সবচেয়ে বড় সংখ্যাগুলোও থাকে তাদের একদম **পেছনে**!

তাহলে বুদ্ধিমানের কাজ হলো:
> আমরা দুটো অ্যারের **সবচেয়ে বড় সংখ্যা দুটোর মধ্যে তুলনা করব**। যে বড় হবে, তাকে নিয়ে `nums1`-এর **একদম পেছনের খালি ঘরে** বসিয়ে দেব! 

এতে আমাদের কোনো আসল ডাটা মুছবে না, কারণ আমরা লিখছি ফাঁকা জায়গায়!

## ৪. 🛠️ ৩টি পয়েন্টার (Pointers) দিয়ে সমাধান

আমরা ৩টি মার্কার বা পয়েন্টার ব্যবহার করব:
* `p1 = m - 1` $\rightarrow$ `nums1`-এর শেষ আসল সংখ্যার ইনডেক্স।
* `p2 = n - 1` $\rightarrow$ `nums2`-এর শেষ সংখ্যার ইনডেক্স।
* `p = m + n - 1` $\rightarrow$ `nums1`-এর একদম শেষ ইনডেক্স (যেখানে আমরা বড় সংখ্যাটি বসাব)।

```text
nums1 = [ 1,  2,  3,  0,  0,  0 ]
                  ^           ^
                  p1          p

nums2 = [ 2,  5,  6 ]
                  ^
                  p2
```

## ৫. 🎬 ধাপে ধাপে ভিজ্যুয়াল ড্রাই রান (Visual Dry Run)

ধরি:
- `nums1 = [1, 2, 3, 0, 0, 0]`, `m = 3`
- `nums2 = [2, 5, 6]`, `n = 3`
- শুরুতে: `p1 = 2` (মান: 3), `p2 = 2` (মান: 6), `p = 5` (শেষ খালি ঘর)

| ধাপ | `nums1[p1]` | `nums2[p2]` | কে বড়? | আমরা কী করব? | `nums1`-এর বর্তমান অবস্থা |
|:---:|:---:|:---:|:---:|:---:|:---|
| **১** | `3` | `6` | $6 > 3$ | শেষ ঘরে `6` বসাই (`nums1[5] = 6`)। `p2` ও `p` ১ কমাই। | `[1, 2, 3, 0, 0, 6]` |
| **২** | `3` | `5` | $5 > 3$ | এবার `5` বড়। শেষ ঘরে `5` বসাই (`nums1[4] = 5`)। `p2` ও `p` ১ কমাই। | `[1, 2, 3, 0, 5, 6]` |
| **৩** | `3` | `2` | $3 > 2$ | এবার `3` বড়! তাই `nums1[3] = 3` বসাই। `p1` ও `p` ১ কমাই। | `[1, 2, 3, 3, 5, 6]` |
| **৪** | `2` | `2` | সমান | `nums2`-এর `2` বসিয়ে দিই (`nums1[2] = 2`)। `p2` ও `p` ১ কমাই। | `[1, 2, 2, 3, 5, 6]` |
| **শেষ**| - | `p2 = -1` | `nums2` শেষ | `nums2`-এর সব বসানো শেষ! লুপ বন্ধ। | **`[1, 2, 2, 3, 5, 6]` (Merged!)** |

## ৬. 🌟 জুনিয়র ডেভেলপার প্রো-টিপ: কেন শুধু `while (p2 >= 0)`?

কোডে খেয়াল করবেন আমরা লুপ চালিয়েছি শুধু `while (p2 >= 0)`:
* যদি `nums2` আগে খালি হয়ে যায় (যেমনটা উপরের ধাপে হলো), তাহলে `nums1`-এর বাকি যে সংখ্যাগুলো সামনে পড়ে আছে (`1, 2`), সেগুলো তো **আগে থেকেই সঠিক জায়গায় সুন্দরভাবে বসে আছে!** সেগুলোকে আর নাড়াচাড়া করার কোনো প্রয়োজন নেই।
* আর যদি `nums1` আগে খালি হয়ে যায় (`p1 < 0`), তখন `nums2`-এর বাকি সংখ্যাগুলো একে একে সামনে বসে যাবে।

## ৭. ⏱️ কমপ্লেক্সিটি অ্যানালাইসিস (Complexity Analysis)

* **টাইম কমপ্লেক্সিটি (Time Complexity): $O(m + n)$**
  * লুপের প্রতি ধাপে `p` এক ঘর করে পেছনের দিকে আসে।
  * সর্বমোট আমরা $m + n$ টি সংখ্যাকে ১ বার করেই স্পর্শ করছি। তাই এটি রৈখিক বা Linear Time।
* **স্পেস কমপ্লেক্সিটি (Space Complexity): $O(1)$**
  * আমরা অতিরিক্ত কোনো অ্যারে নেইনি। শুধু মাত্র ৩টি ইনটিজার পয়েন্টার (`p1`, `p2`, `p`) নিয়েছি। তাই মেমোরি খরচ শূন্য (Constant Space)।
